# 01 · Vision

## One-liner

**Simplr is a to-do app for macOS that's a pleasure to touch.** Lists and kanban boards, a Liquid Glass progress slider
you'll want to drag just for fun, and one-click shortcuts that take you straight to the app or website a task is about.

## The problem (honestly)

Most to-do apps are optimised for productivity and end up feeling like spreadsheets. People abandon them not because
they lack features but because opening them feels like a chore. Simplr bets the other way: **if the app is satisfying
to use, you'll keep coming back to it** — and the tasks get done as a side effect.

It's allowed to be "a bit useless". Delight is the feature.

## Who it's for

| Persona | Need |
|---|---|
| **Me (primary)** | A daily driver for personal tasks, and a playground to learn Swift, SwiftUI and macOS APIs. |
| **Portfolio visitor** (recruiter, dev, PM) | Evidence that I can set a product vision, scope it, run a board and ship a polished app. |
| **Mac users who like pretty tools** (secondary) | A tasteful, native-feeling to-do app that doesn't try to be Jira. |

## Pillars

1. **Feels great** — Liquid Glass everywhere it makes sense; every interaction has motion, colour or haptic feedback.
2. **Native Mac** — sidebar, menu bar, global hotkey, keyboard-first. It should feel like Apple could have shipped it.
3. **Gets you there** — a task can link to the app or website you need to do it; one click and you're in.
4. **Keeps you coming back** — streaks and a satisfying completion moment, without nagging.

## Non-goals (for now)

- Team collaboration, sharing, assignees.
- Cross-platform beyond Apple. (iOS comes *after* the Mac MVP.)
- App Store distribution. The repo is the product showcase; builds are shared via GitHub Releases.

## Success criteria for the MVP (v1.0)

- [ ] I use it as my actual to-do app for 2 consecutive weeks.
- [ ] All **Must** stories in [Scope](02-scope.md) are done and demoable in a ≤60 s screen recording.
- [ ] The repo has a README with screenshots/GIF, these docs, and a public board showing the work.
- [ ] A signed/notarised (or at least ad-hoc signed) `.app` is attached to a GitHub Release.
